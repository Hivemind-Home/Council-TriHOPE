## 2. Machine and setup

One 96 GB GPU is enough; two cards halve the wall clock (`--parallel-gpus 2`
instead of `--concurrent`). Disk: ≥ 300 GB free (E5 keeps every tagged
checkpoint, ~1.9 GB each, across 21 runs).

```bash
git clone https://github.com/Hivemind-Home/Council-TriHOPE.git && cd Council-TriHOPE
git log --oneline -1                       # 371fad0 or later
sudo apt-get install -y python3.12-dev build-essential   # Triton needs Python.h (use your python's minor version)
python -m venv .venv && source .venv/bin/activate && pip install -e ".[dev,data,analysis]"
python -c "import torch; print(torch.cuda.is_available())"     # True
python -m pytest tests/ -q                 # 512 passed, 2 GPU-only tests run for real here
python -m hivemind preflight --config-name stream_small --metadata-only
for m in baselines_small r_tier_small budget_sweep_small p_study_small ablation_grid bad_teacher_small live_kd_small; do
  python scripts/run_experiment.py configs/experiments/$m.yaml --dry-run; done
```

Set `HF_HOME` to a large disk before the first run (datasets ≈ 2 GB, the
four live teachers ≈ 16 GB if you rerun Tier 4). Run everything inside
`tmux`.

Observed per-run footprint (0.6B student, bf16, batch 2): cache mode
≈ 13 GB (12 + 0.6 tracked moments), `full_ft` higher, live-KD ≈ 30 GB.
Cache-mode runs: ~4 it/s alone; N concurrent runs share compute, so
`--concurrent 5` fills the card and finishes the matrix in roughly the
sequential time ÷ 1 (throughput-bound), i.e. ~1.3 h × runs / 5 wall.

## 3. Step A — the gate run and the one open decision (do this first)

```bash
python scripts/run_experiment.py configs/experiments/baselines_small.yaml --only trihope
```

Three seeds, sequential, ~1.3 h each. After the **first** seed passes
step 1000, before anything else launches:

```bash
python scripts/diagnose_p.py runs/baselines_small_v1/trihope-seed1337
```

Healthy: C̄ spread over (0, 1) from `general_warm` on (not 0.000), surprise
mostly < 20, a non-zero P count by the end of `code_recurrent`.

**The decision.** With the current defaults (`surprise_high 2.0`,
`repetition_low 0.3`) the live run routed only 12 % of `novel_inject` to
R: a pretrained student's surprise rarely clears 2.0, and the momentum
term of repetition carries over between phases so novel rows rarely drop
below 0.3. E2 and the R-tier claim need novel rows to actually reach R.
Read the `novel_inject` block of the cache-mode diagnostic: if its R share
is well under half, set the E1 defaults in `configs/stream_small.yaml`
(`controller.policy.surprise_high` ≈ the novel-phase S p50, e.g. 1.5;
`controller.policy.repetition_low` ≈ 0.4) **before** launching the
matrix, delete the trihope seeds, and rerun step A. Every baseline
inherits these values; changing them after the matrix means rerunning it.
The E3 sweep already spans surprise {1, 2, 4} × repetition_low
{0.2, 0.3, 0.45}, so the curve is covered either way.

## 5. Health checks that catch the failures we already hit

| Symptom | Meaning |
|---|---|
| runner prints the launch line, then nothing | normal: output goes to `<run>/stdout.log`; `status.json` says `running` |
| `Python.h: No such file` on the first forward | install `python3.X-dev`, relaunch with `--resume` |
| `Key 'X' is not in struct` | should no longer happen for manifests; by hand use `++key=value` |
| bar sits at 499 / 1999 / 2149 / … | phase-boundary eval (exact-match generation); also every 250 steps |
| `diagnose_p.py` shows C̄ max 0.000 everywhere | the run predates `5788dac`; delete and rerun |
| a live run with `loss/kd` = 0 | predates `f9b422d`; delete and rerun |
| `surprise_gate` with consolidations > 0 | predates `371fad0`; delete and rerun |
| `permanent_writes.total == 0` at the end | P never fired — `diagnose_p.py` says which conjunct blocks |
